# 平台与 Widget 会话统一和续聊实施计划

设计：[平台与 Widget 会话统一和续聊](../design/2026-11-19-unified-conversation-history-design.md)。

## 2026-11-19 已实施的同源 Widget 方案

1. FastAPI 增加 Widget 显式复用平台认证分支，保留站点检查；在话题存储共用授权谓词，将已验证账号用于话题、消息、任务及文件。增加话题响应来源字段。
2. Vue Chat 使用混合列表及独立的来源筛选，管理员跨用户查阅单独按权限启动。Widget 接入增加同源配置与说明，使用同一会话接口和登录会话。
3. 定向验证站点及账号隔离、匿名行为不变、列表来源切换和只读模式。使用启用登录的本地预览，在两个入口看到同一话题并验证消息和任务状态；没有真实模型配置时如实注明。
4. 前后端一起部署，Widget 接入显式启用，无数据迁移。移除接入配置即可退回原来的宿主身份模式。

管理员权限补充：先收紧运行接口到本人会话，通过管理员只读路由辅助查阅消息和文件，校验为管理员且会话不属于调试预览。前端在管理详情复用文件树和消息附件，并更新反馈、记忆的直达链接。定向测试覆盖请求的角色和所有权、真实文件下载、隔离路径与继续聊天拒绝；使用本地登录预览验证图片和下载。

本地验证：前端 97 项、后端合同与存储单测 57 项通过，另用真实 MySQL 验证两个站点、不同大小写账号 ID 与旧 Widget 记录的归属隔离。平台和 Widget 生产构建通过。Chromium 从 Widget 发起会话，全屏打开平台续聊，再回到 Widget 读取两次回复；同一话题 ID 下两次任务都持久化终态和 SDK 事件。环境为本机 Docker MySQL `127.0.0.1:3326/dataagent_conversation_preview`、Docker Redis `127.0.0.1:6389` DB 14、项目 Python 3.13 和 Pi。模型响应由本地模拟服务给出，未调用真实模型或数据源。

管理员权限验证：147 项后端测试、2 项真实 MySQL 测试、54 项相关前端测试及前端生产构建通过。Chromium 使用管理员登录，从反馈打开另一用户的 Widget 会话，通过消息附件和文件面板分别预览图片，并下载校验了 CSV；平台与 Widget 的他人会话均拒绝运行入口的发送和编辑。管理模式隐藏输入区，管理员自己的会话仍能发送、流式接收并在同一预览环境持久化回复，使用本地模拟模型。

本轮调整：用管理员会话 API 的逐条 `can_continue` 替换前端模式切换。管理员列表保留按助手、来源和用户查看，补后续页加载，选中会话保持独立于列表筛选。统一反馈与记忆 URL。验证点击自己的会话能发送、点击他人的会话没有发送入口且还能访问文件、发起新会话随时可用，以及旧链接可正常打开。

## 独立登录 Widget 的账号归属（2026-11-23）

[设计及接入核对](../design/2026-11-19-unified-conversation-history-design.md#独立登录-widget-的账号归属2026-11-23)。

1. 核对外部来源绑定、实际 `sub`、管理员及两份助手名单。记录每个助手的已发布生效名单、草稿差异和无法映射的用户。由管理员在切换前确认生效授权，通知 MCP 令牌持有人重新申请。
2. 切换时暂停写入、令牌签发及定时触发，等待在途任务结束。备份配置和授权记录。DataAgent 增加用户、外部身份、角色、用户角色、助手授权表（用户只停用不物理删除）。按盘点表新增整数外键，一次性导入旧管理员（OAuth 管理员仅 OAuth 登录，不设默认密码）、为旧会话和已发布名单中的旧主体登记普通账号，并导入已发布的有效授权，草稿差异只出清单，清除草稿、发布快照与已发布配置的旧名单。按 `da_user_identity` 精确匹配旧 `da_agent_topic.auth_user_id`（`local:<u>` / `<provider>:<sub>`）回填 `da_agent_topic.user_id`，未映射行保留 `user_id` 为空且仅管理员可读，代码仅保留 `user_id` 归属路径。直接删除 `da_mcp_access_token` 旧行（或重建表），再修改 `user_id` 为整数外键。保持历史话题字段。回退时恢复旧应用、旧字段结构、配置及授权数据，MCP 令牌由用户重新申请。
3. 后端以 `core/accounts` 统一账号解析、注册及权限。网站范围随请求上下文传入，用户定时和队列任务按持久化的整数账号执行同一助手权限规则。经验提炼继续由内置后台助手执行，系统记录的 `user_id` 留空。移除身份头和角色的旁路解析及匿名业务入口。前端沿用工作台用户选择器，角色页只读展示静态菜单权限。工作台与角色管理统一使用独立的助手授权接口，保存及发布草稿只写助手配置。更新公开接口、部署和 Widget 文档。
4. OpenDataWorks 仓库增加已认证的个人 Widget 转发，覆盖悬浮与嵌入、SSE、附件和取消。OntoFoundry 仓库更新 `DataAgentClient` 与建模 BFF，校验工作空间权限后向 DataAgent 转发已登录用户和站点凭据，读时对账使用会话创建人 `created_by`，只允许会话创建人发问。已绑定旧共享话题的建模会话只展示历史，新发问使用新话题。三个仓库各自提交 PR，在一个切换窗口内按 DataAgent 接口就绪、两端宿主连接验证的顺序联动部署。
5. 将匿名冒烟脚本和 `AGENTS.md` 改为先配置本地账号、调用 `POST /api/v1/nl2sql/auth/login` 并用同一凭据发起话题、任务和事件请求。builtin、DeepEval、Opik 评测沿用已有登录 Bearer 请求支持，将有效会话凭据纳入默认运行步骤。定向验证并发注册、默认密码和改密、身份绑定冲突、角色撤销、旧令牌及匿名请求被拒，以及三种助手模式。覆盖未发布助手配置授权、存草稿与重发均不改已保存授权。通过实际宿主和主站登录验证个人 Widget、同源 Widget、MCP 新令牌和同账号续聊。用 OntoFoundry 两个已登录成员验证共享，另用错会话键、错站点与旧话题写入验证隔离。确认旧历史可读，新会话可以执行，并完成任务终态、SSE、消息和附件校验。
