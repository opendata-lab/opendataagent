# 知识设计

日期：2026-11-19 初版；2026-11-26 整体修订（取消“记忆”，只保留知识；知识文档化；按需读取；对话中显示知识检索）
计划：[implementation plan](../plans/2026-11-19-experience-library-plan.md)

## 当前状态

- 数据在 `da_agent_experience`，管理接口 `/api/v1/nl2sql-admin/experiences`（`require_admin`）。条目分 `kind`（knowledge/memory），有 `title`（40 字）、`when_text`（120 字）、`content`（TEXT，API 字段 `body`，500 字）、`inject_mode`（always/on_demand）、`status`（pending/active/disabled）、`scope`（global/agent）。
- 知识只能由管理员新增，直接生效；记忆只由每日总结产生，初始 pending，审核后生效。主导航有 `/knowledge`、`/memories` 两个页面。
- 每日总结（`core/experience.py` `run_daily_digest`）：每个智能体取前一天结束的任务（完成或失败，不含预览会话），点踩 → 失败 → 点赞 → 其余按完成时间排序，最多 30 个；每个任务给出用户问题、中间过程（工具调用、输入、成败、输出开头、错误）、最终回答摘要和用户评价。内置总结智能体按 `.claude/skills/experience-digest/SKILL.md` 提炼最多 5 条执行方法，并明确不写业务口径。
- 运行时（`core/task_executor.py` → `prepare_injection`）：always 条目在 1000 字预算内把全文写进系统提示词；on_demand 条目按更新时间最多 30 条，在系统提示词中列“标题（适用条件）→ 路径”，全文写到只读挂载 `/opt/skills/_knowledge_memory/<sha256(id)>.md`，由模型用 read 读取。执行段结束清理，每段重建。部署开关默认关闭。
- 管理员反馈页 `/feedback`（含“用户”列）已按初版实现，本次不改。
- 对话界面按工具名关键字推断工具类型和图标（`packages/agent-conversation/src/core/toolPresentation.js` `describeToolAction`）。

## 问题

1. “记忆”在同类产品里是个人概念（ChatGPT Memory、Windsurf memories 都按用户沉淀），而我们的条目由管理员审核、对助手的所有用户生效，容易误解；知识与记忆两个页面、两套规则增加理解成本。
2. 知识只能是 500 字短条目，放不下口径文档、指标说明这类长文档。
3. `inject_mode` 与 1000 字预算让配置变复杂；混排索引里条目增多会把知识挤出 30 条上限。
4. 每日总结不能沉淀业务口径，而口径恰是对话中最常被用户纠正的内容。
5. 用户在对话中看不出模型查阅了知识：读取知识文件显示为普通的“读取文件”，路径是哈希文件名。
6. 工具图标不准（2026-11-26 用户报告并核实）：MCP 工具在 Pi 中按原名注册、没有 `mcp__` 前缀（`dataagent-runtime-pi/src/mcp/mcp-client.ts`），而前端只靠 `mcp__` 前缀排除 MCP，再按名称子串分类。用本地会话记录中的真实工具名验证：`odw_search_tables`、`search_ontology` 被判为“搜索文件”并显示放大镜图标；Pi 内置的 `find` 反而显示为通用“执行工具：find”。

## 方向与原则

- 用户决定（2026-11-26）：取消“记忆”，只保留“知识”；全部按需读取；方向要对，初期保持简洁；不自造轮子。
- 闭环：每日总结 → 待审核知识 → 管理员审核生效 → 运行时按需读取 → 用户评价 → 下一次总结。
- 使用方式沿用 Claude 处理 skills 和查代码的模式：模型始终看到“有哪些知识”（标题 + 适用场景，相当于 skill 的 name + description），正文按需读取；检索由模型自己完成——把问题扩展成同义词、英文名、表名、指标名等多组关键词去 grep，结果不够再换词（与 Claude 做 web search 时自己拟定多组查询相同）。后端不另加“改写问题”的模型调用，第一期也不做运行前检索。

## 方案

### 1. 数据与生命周期

- **只有知识一种条目**，来源两类：
  - 管理员添加：手写或上传 .md/.txt（浏览器读取文件内容填入正文，不新增上传接口），保存即生效；
  - 每日总结：提炼为待审核（pending）知识，附来源任务，管理员审核后生效。
- 字段：`title`（40 字）、`when_text`（适用场景，120 字）、`body`（20000 字）、`status`（pending/active/disabled）、`scope`（global/agent）。`content` 由 TEXT（65,535 字节，2 万汉字 utf8mb4 约 60KB，会超）改为 MEDIUMTEXT。
- 删除 `kind` 与 `inject_mode`：迁移把现有 memory 行原样转为知识（保留状态与来源）；删除“始终注入”与 1000 字预算。迁移说明提醒管理员：原“始终注入”的硬性规则应移入智能体系统提示词。表名 `da_agent_experience`、模块名与接口路径不改。
- 状态流转：
  - pending 只能由每日总结产生；审核可编辑后“生效”（active）、“忽略”（disabled，可恢复）或删除；
  - active ⇄ disabled 可互转；已审核条目不能退回 pending；删除为永久删除。
  - 智能体专用条目可提升为全局。
- 修改、停用、删除只影响之后开始的任务；已经读进会话的内容不撤回（与已生成的回答一致）。

### 2. 每日总结

- 任务选择与输入不变（见“当前状态”）。
- 产出范围放开（用户 2026-11-26）：除执行方法外，也可以提炼业务口径（如“销售额应排除退款”），前提是对话里有依据（用户纠正或确认过），并列出来源任务；是否采纳由管理员审核把关。仍不写具体数值、客户名、查询结果和只在单个任务成立的细节。单条正文保持 ≤500 字，每天最多 5 条。
- skill 用词“经验/经验库”统一改为“知识”。

### 3. 运行时使用

- **知识目录**（系统提示词，沿用现有索引位置）：列出本智能体可见的生效知识“标题（适用场景）→ 路径”，按更新时间倒序最多 100 条；超出时注明“另有 N 篇未列出，用 grep 搜索知识目录”。目录只随知识增删改变化，不随问题变化。
- **正文文件**：沙箱只读挂载 `/opt/skills/_knowledge/`（原 `_knowledge_memory`），文件名沿用 `sha256(experience_id).md`，文件首行为 `# 标题`、次行为适用场景，之后是正文；仅含本智能体可见的生效知识。写文件、目录、预览共用一个路径函数。执行段结束清理、每段重建（现有机制，卡片恢复也重建）。
- **提示词约定**（固定文本）：知识不得覆盖当前请求、技能约定或权限规则；根据目录判断相关知识并读取；目录看不出时，把问题扩展成多组关键词用 grep 搜索 `/opt/skills/_knowledge/`；长文档先 grep 定位，再用 read 的 offset/limit 分段读。
- **预览**：智能体页预览显示目录与将写入系统提示词的文本；预览与运行共用资格判断（部署开关、排除每日总结智能体）。

### 4. 对话中的展示

- **知识检索单独成类**：工具调用的路径或命令指向 `/opt/skills/_knowledge/` 时，显示为知识类，使用书本图标：
  - `read` → “查阅知识”，详情显示知识标题（从读取结果首行 `# 标题` 取；结果未返回前显示“查阅知识”）；
  - `grep` / `find`，以及 `bash` 中针对该目录的 grep/rg → “搜索知识”，详情显示搜索关键词。
  - 知识目录路径作为前端常量，与后端 `INJECTION_ROOT` 保持一致（后端测试断言两处相同）。
- **工具分类改为按名称精确匹配**（修复问题 6）：
  - 只对已知内置工具名（大小写不敏感）给出文件类展示：`bash` → 执行命令，`read` → 读取文件，`write`/`edit` → 修改文件，`ls` → 查看目录，`grep`/`find`/`glob` → 搜索文件，`skill` → 执行技能；
  - 其余工具（MCP、自定义工具）一律按通用工具显示名称和扳手图标，不再按名称子串或参数形状推断；
  - 已有的结构化结果（SQL、图表、Python）展示不变。
  - 此项是现有缺陷，代码改动单独成 PR，先于知识修订合入。

## 涉及范围

Vue 管理页与对话组件（`packages/agent-conversation`）、FastAPI、MySQL Alembic、task executor、每日总结 skill。不改 Pi 协议、Pi 扩展与 Docker 挂载实现。

## 取舍

- 不做运行前检索：目录 + 模型自主 grep 在知识量不大时足够，且不新增机制、不影响提示词缓存。目录满 100 条或实测常漏读时再加（见后续）。
- 知识检索的展示按挂载路径识别，而不是新增专用工具：路径是后端固定约定，第一期不增加工具与协议。若后续加 `search_knowledge` 工具，展示改按工具名识别即可。
- 放开总结写业务口径后，管理员审核是口径进入知识的唯一把关环节；审核界面突出显示来源任务链接。
- 每日总结只新增条目，不修改或合并已有知识，重复与矛盾靠审核处理；“与已有知识相似”的提示列为后续。
