# 运行中发送消息的排队与立即发送设计

日期：2026-11-19
状态：待评审
关联计划：[2026-11-19-message-queue-plan.md](../plans/2026-11-19-message-queue-plan.md)

## 1. 现状

- 对话组件（`packages/agent-conversation`）在运行中只显示停止按钮，不能发送；用户只能等待或停止后再输入。DataAgent 主站、Widget 和 OntoFoundry 建模页都用这个组件。
- 后端已有 `da_agent_message_queue` 表和增删改、`consume` 接口（主要服务于定时消息），前端没有界面使用，任务结束后也不会自动消费。
- OntoFoundry 在会话运行中拒绝新消息（`SESSION_RUNNING`，HTTP 409）；运行成功后处理结果期间同样拒绝（`RESULT_PROCESSING`，HTTP 409）。它在转发前给消息加上运行上下文，并在建模会话上记录任务 ID。

## 2. 目标

与常见 Agent 客户端一致：运行中可以继续输入，消息排进队列，运行结束后按顺序发送；对任一排队消息点「立即」可停止当前运行并马上发送它。三个宿主同时生效。

## 3. 用户决定（2026-11-19）

| 问题 | 决定 |
| --- | --- |
| 「立即」的含义 | 停止当前运行，再发送该消息（不在运行中途插入） |
| 未点「立即」的排队消息 | 当前运行成功结束后自动按顺序发送；运行失败或被取消时暂停，等用户处理 |
| 范围 | DataAgent 主站、OntoFoundry 建模页、Widget |

## 4. 方案

### 4.1 队列放在对话组件里

队列保存在组件内存中（`ConversationRoot.vue`），不用后端的消息队列表：

- 三个宿主都经由同一个 `transport.sendMessage` 发消息。由组件在运行结束后再发，OntoFoundry 的上下文包装、会话任务记录和权限检查都照常生效；若由 DataAgent 后端自行消费队列，会绕过 OntoFoundry。
- 不新增接口、表和事件，宿主无需改代码。
- 代价：刷新页面或切换会话后队列丢失，关闭页面后不会继续发送。常见 Agent 客户端同样如此。

### 4.2 交互

- 运行中按 Enter 或点「加入队列」按钮（运行中有内容时与停止按钮并列），当前输入和附件进入队列，输入框清空。附件此时已上传，随消息保存引用。
- 输入框上方显示队列：序号、内容摘要、附件数，以及「立即」「编辑」「删除」。
- 运行状态变为 `finished`：发送队首；它开始新的运行，后续消息等这一轮结束。
- 运行状态变为 `failed` 或 `cancelled`：队列暂停，显示「上一轮未完成，已暂停自动发送」；用户点任一条的「立即」即发送，或手动发一条新消息（其成功结束后队列继续）。
- 「立即」：把该条移到队首；若正在运行，先停止运行，运行进入终态后立即发送；若未运行，直接发送。
- 「编辑」：输入框为空时，把该条放回输入框并移出队列；输入框有内容时提示先处理当前输入，不覆盖。
- 等待权限确认或提问回答的运行也算运行中，消息同样排队；「立即」会取消这次等待。

### 4.3 宿主忙时重试

宿主答复 HTTP 409 表示暂时不能开始新运行（如 OntoFoundry 处理上一轮结果）。队列发送遇到 409 时不报错，按 1、2、4、6、8 秒重试，约 20 秒后仍失败才报错并暂停。为此：

- `ConversationError` 增加 `status`（HTTP 状态，非响应错误为 0），`errorFromResponse` 填入；类型声明同步。
- `useConversation.send` 增加 `quietBusy` 选项：遇到 409 返回 `'busy'`，不触发错误事件。
- BFF 协议文档说明：暂时不能开始运行时返回 409。

## 5. 接口变化

- 新增样式部件：`queue`、`queue-item`、`queue-send-now`、`queue-edit`、`queue-remove`。
- `ConversationError.status`（新增只读字段）。
- 其余公开 API、事件和宿主协议不变。

## 6. 取舍

- **不在运行中途插入消息**：用户选择了「停止再发」。Pi 支持把消息插入运行中的下一步（steer），以后如需可在此基础上加，不影响队列。
- **不持久化队列**：持久化要决定跨设备、跨标签页的归属和谁来消费，复杂度与收益不相称。
